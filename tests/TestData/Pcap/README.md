# Fixed PCAP reference files

These files consist of literal, hand-specified bytes. They are not generated by a PacketLab
writer (there is no writer). Tests assert their decoded values independently.
The files in `tests/TestData/Pcap/` are fixed inputs for PCAP and Analysis integration
tests, CLI E2E tests, and the Native AOT smoke executable. Each consumer explicitly
copies its required files to `TestData/Pcap/` in its build and publish output.
The single-packet files and `multiple.pcap` have arbitrary payloads for testing the
PCAP container independently. The Ethernet files exercise protocol analysis.

All samples use version 2.4, SnapLen 65535, raw LinkType 1 and zero Reserved1/Reserved2.
The four single-packet files are each 43 bytes: 24-byte file header, 16-byte record header,
and `DE AD BE`. Captured length is 3; original length is 5. Seconds are `0x01020304`
(16909060); fractions are 123456 for microseconds or 123456789 for nanoseconds.

| File | Byte order | Precision | Magic bytes |
| --- | --- | --- | --- |
| little-micro.pcap | Little endian | Microseconds | D4 C3 B2 A1 |
| big-micro.pcap | Big endian | Microseconds | A1 B2 C3 D4 |
| little-nano.pcap | Little endian | Nanoseconds | 4D 3C B2 A1 |
| big-nano.pcap | Big endian | Nanoseconds | A1 B2 3C 4D |

`multiple.pcap` is a 77-byte little-endian, microsecond file with the following records.
The second record starts at byte 43 and the third at byte 61, without alignment padding.

| Record | Seconds | Raw fraction | Captured | Original | Payload |
| --- | --- | --- | --- | --- | --- |
| 1 | 100 | 1500000 | 3 | 5 | DE AD BE |
| 2 | 99 | 0 | 2 | 1 | AA BB |
| 3 | 98 | 0 | 0 | 0 | Empty |

This covers an unnormalized timestamp, decreasing times, historical length metadata,
non-aligned records and an empty packet. Expected CLI packet count: 3.

`ethernet-little.pcap` and `ethernet-big.pcap` contain the same five records using
little-endian and big-endian PCAP headers respectively, with microsecond precision.
Each is 171 bytes. Record seconds are 1 through 5 and fractions are zero.
Ethernet fields use network byte order in both files.

| Record | Captured | Original | Payload hex | Analysis |
| --- | --- | --- | --- | --- |
| 1 | 14 | 60 | FFFFFFFFFFFF0200000000010806 | Ethernet II, source 02:00:00:00:00:01, broadcast destination, EtherType 0x0806 |
| 2 | 3 | 3 | 010203 | Incomplete Ethernet header |
| 3 | 14 | 1514 | 00112233445566554433221105DC | Unsupported IEEE 802.3 length 1500 |
| 4 | 14 | 14 | 00112233445566554433221105DD | Invalid Length/Type 1501 |
| 5 | 22 | 60 | 0011223344556655443322118100002A0800ABCD0000 | Ethernet II, EtherType 0x8100, remaining bytes 002A0800ABCD0000 |

Records 3–5 have source 66:55:44:33:22:11 and destination 00:11:22:33:44:55.
Frame diagnostics do not prevent record 5 from being analyzed. Expected CLI packet
count: 5; `pcap inspect` prints all five records and exits successfully.
